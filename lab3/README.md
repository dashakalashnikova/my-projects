### Завдання №3 (Таблиця 2, №13)

#### 1. Формулювання
Обчислити нескінченну суму із заданою точністю $\varepsilon$ ($\varepsilon > 0$):
$$\sum_{i=1}^{\infty} \frac{(-1)^i}{i!}$$
Вважати, що необхідна точність досягнута, якщо черговий доданок виявився по модулю меншим, ніж $\varepsilon$. Цей і всі наступні доданки можна не враховувати.

#### 2. Математичний аналіз та оптимізація
- **Теоретичне точне значення:**
  Відомо, що розклад експоненти в ряд Тейлора:
  $$e^x = \sum_{i=0}^{\infty} \frac{x^i}{i!} = 1 + \sum_{i=1}^{\infty} \frac{x^i}{i!}$$
  При $x = -1$:
  $$e^{-1} = 1 + \sum_{i=1}^{\infty} \frac{(-1)^i}{i!} \implies \sum_{i=1}^{\infty} \frac{(-1)^i}{i!} = e^{-1} - 1 = \frac{1}{e} - 1 \approx -0.6321205588285577$$
- **Рекурентне обчислення доданків:**
  Щоб уникнути переповнення розрядної сітки факторіалом ($i!$) при великих $i$, наступний доданок обчислюється через попередній:
  $$a_1 = -1.0, \quad a_i = -a_{i-1} \cdot \frac{1}{i}$$
- **Умова зупинки:**
  Цикл триває доти, доки $|a_i| \ge \varepsilon$. Як тільки $|a_i| < \varepsilon$, цей доданок не додається до суми і цикл негайно зупиняється.

## Частина 2. Відповіді на контрольні запитання

### 1. Що таке структурне програмування?
**Структурне програмування** — це методологія (парадигма) розробки програмного забезпечення, що базується на представленні програми у вигляді чіткої ієрархічної структури блоків без використання безладних безумовних переходів (`goto`). Програма формується з трьох базових керуючих конструкцій: слідування (послідовність), розгалуження (вибір) та повторення (цикл), кожна з яких має строго одну точку входу та одну точку виходу.

### 2. Назвіть основні конструкції структурного програмування.
Згідно з фундаментальною теоремою Бома — Джакопіні (Böhm–Jacopini theorem), будь-який обчислюваний алгоритм може бути реалізований за допомогою трьох базових керуючих конструкцій:
1. **Послідовність (Sequence / слідування):** виконання інструкцій послідовно одна за одною у порядку їх запису.
2. **Розгалуження (Selection / умовна конструкція):** вибір одного з альтернативних напрямків виконання залежно від істинності певної логічної умови (`if`, `if-else`, `switch`).
3. **Повторення (Iteration / цикл):** багаторазове повторення виконання блоку інструкцій за умови виконання певного предикату (`while`, `do-while`, `for`).

### 3. Назвіть основні принципи структурного програмування.
1. **Принцип спадного проектування (Top-Down Design):** розбиття глобальної задачі на підзадачі від загального до конкретного з поступовою деталізацією.
2. **Принцип модульності:** поділ коду на функціонально завершені та незалежні блоки (підпрограми, методи, класи) з чітко визначеними інтерфейсами передачі даних.
3. **Принцип однієї точки входу та однієї точки виходу (Single Entry, Single Exit):** кожен блок коду, цикл чи метод повинен мати лише один вхід і один вихід, що унеможливлює неконтрольовану передачу керування.
4. **Відмова від безумовних переходів (`goto`):** уникнення довільних стрибків у коді, що забезпечує високу читабельність, простоту верифікації та легкості тестування.

### 4. Поясніть, чому в більшості мов програмування не радять використовувати оператор GOTO, а в мові Java його взагалі немає?
- **Чому не радять:** Оператор `goto` дозволяє здійснювати перехід у будь-яку ділянку коду, руйнуючи ієрархічну структуру програми. Це ускладнює розуміння контексту стану змінних, створює приховані залежності та перетворює код на «спагеті», що надзвичайно важко супроводжувати, тестувати й оптимізувати компіляторам. Відома праця Едсгера Дейкстри 1968 року «Go To Statement Considered Harmful» обґрунтувала згубність безумовних переходів.
- **У мові Java:** Слово `goto` є зарезервованим ключовим словом (`reserved keyword`), проте самого оператора в мові **не існує** (якщо спробувати його використати, виникне помилка компіляції). Творці мови зберегли слово як зарезервоване, щоб попередити помилки розробників, які переходили з C/C++, а для потреби виходу з кількох рівнів вкладених циклів надали безпечну альтернативу — іменовані мітки в операторах `break label;` та `continue label;`.

### 5. Що таке спагеті-код?
**Спагеті-код (Spaghetti code)** — це антипатерн програмування, що описує програму із заплутаною, хаотичною структурою керування потоком виконання (найчастіше спричиненою зловживанням `goto`, надмірною кількістю неструктурованих умов або відсутністю модульності). Читання та налагодження такого коду нагадує розплутування клубка переплетених спагеті: модифікація чи виправлення в одній ділянці коду несподівано ламає зовсім іншу, здавалося б, непов'язану частину програми.

### 6. Що таке проектування зверху-вниз? В чому його переваги?
**Проектування зверху-вниз (Top-Down Design, покрокова деталізація):** це підхід до архітектури та розробки програмного забезпечення, за якого складна система спочатку описується в цілому на найвищому рівні абстракції, після чого вона послідовно розбивається на простіші компоненти (підпрограми, методи, класи), доки кожен фрагмент не стане елементарним і простим для реалізації.
**Переваги:**
- Зниження складності мислення на ранніх етапах розробки шляхом фокусування на логіці системи без заглиблення в низькорівневі деталі.
- Зручність командної роботи: інтерфейси методів проектуються нагорі, після чого реалізація окремих частин може паралельно доручатися різним розробникам.
- Легкість тестування та налагодження: на верхніх рівнях можна використовувати методи-заглушки (stubs) для швидкої верифікації загальної логіки.

### 7. Що таке область видимості ідентифікатора?
**Область видимості ідентифікатора (Scope):** це частина тексту програми (контекст), у межах якої оголошений ідентифікатор (ім'я змінної, константи, типу чи методу) є валідним, відомим компілятору і може бути використаний для доступу до відповідної сутності. Поза своєю областю видимості ідентифікатор є невидимим, а спроба звернутися до нього викликає помилку компіляції (`cannot find symbol`).

### 8. Що таке блок? Як блоки впливають на область видимості?
- **Блок (Block):** це послідовність операторів, обмежена фігурними дужками `{ ... }`.
- **Вплив на область видимості:** Блок створює локальну область видимості (Block Scope). Змінна, оголошена всередині блоку, стає доступною лише від точки її оголошення і до закриваючої дужки `}` цього блоку. Після виходу з блоку змінна знищується (стає недоступною), а виділена пам'ять очищується збирачем сміття (Garbage Collector). Вкладені внутрішні блоки бачать змінні зовнішнього блоку, проте зовнішній блок не має доступу до змінних, оголошених усередині його вкладених блоків.

### 9. Наведіть приклади, у яких випадках краще використовувати наступні оператори та конструкції:
- **`if`:** коли потрібно виконати дію тільки за умови істинності умови, а якщо умова хибна — не робити нічого (наприклад, перевірка аргументу на валідність):
  ```java
  if (k < 1 || k > 30) {
      throw new IllegalArgumentException("Invalid k");
  }
  ```
- **`if-else`:** коли існують рівно два взаємовиключні сценарії розвитку подій:
  ```java
  if (number % 2 == 0) {
      System.out.println("Парне");
  } else {
      System.out.println("Непарне");
  }
  ```
- **ланцюги `if-else if -else if...`:** коли є послідовність складних, взаємовиключних або діапазонних умов:
  ```java
  if (score >= 90) {
      grade = 'A';
  } else if (score >= 75) {
      grade = 'B';
  } else if (score >= 60) {
      grade = 'C';
  } else {
      grade = 'F';
  }
  ```
- **`switch`:** коли значення однієї дискретної змінної або виразу (ціле число, символ, рядок `String` або `enum`) порівнюється на точну рівність із набором фіксованих константних значень:
  ```java
  switch (dayOfWeek) {
      case 1 -> System.out.println("Понеділок");
      case 2 -> System.out.println("Вівторок");
      default -> System.out.println("Інший день");
  }
  ```
- **тернарна умовна операція `?:`:** коли залежно від умови необхідно компактно обчислити одне з двох значень всередині виразу чи присвоювання:
  ```java
  double max = (a > b) ? a : b;
  ```

### 10. Наведіть приклади, у яких випадках краще використовувати наступні оператори та конструкції:
- **`while`:** цикл із передумовою. Використовується, коли кількість повторень наперед невідома і залежить від динамічного стану, причому якщо умова від самого початку хибна — тіло циклу не повинно виконатися жодного разу (наприклад, обчислення суми ряду до досягнення точності $\varepsilon$ або читання з потоку даних):
  ```java
  while (Math.abs(term) >= eps) {
      sum += term;
      term = -term / (++i);
  }
  ```
- **`do-while`:** цикл із післяумовою. Використовується, коли тіло циклу гарантовано має виконатися щонайменше один раз перед тим, як буде перевірено умову (наприклад, введення даних користувачем із повторним запитом у разі помилки або циклічне меню):
  ```java
  do {
      System.out.print("Введіть додатне число: ");
      val = scanner.nextDouble();
  } while (val <= 0);
  ```
- **`for`:** цикл із лічильником (параметром). Використовується тоді, коли кількість ітерацій наперед відома або задана чітким числовим діапазоном / кроком:
  ```java
  for (int i = 1; i <= k; i++) {
      sum += Math.sqrt(m / i) * Math.sin(m * i);
  }
  ```

### 11. Чим оператор `break` відрізняється від оператора `continue`?
- **`break`:** негайно перериває виконання всього поточного циклу (`for`, `while`, `do-while`) або блоку `switch`, передаючи керування на інструкцію, що йде відразу після цього циклу. Подальші ітерації не виконуються.
- **`continue`:** перериває виконання лише **поточної ітерації** циклу. Решта операторів тіла циклу для поточної ітерації пропускається, і цикл негайно переходить до перевірки умови (у `while`/`do-while`) або до виразу оновлення лічильника (у циклі `for`), продовжуючи наступну ітерацію.

### 12. Навіщо у мові Java є мітки, якщо немає `goto`?
Мітки (`labels`) у Java використовуються виключно у зв'язці з операторами `break` та `continue` для керування **багаторівневими вкладеними циклами**.  
За замовчуванням `break` і `continue` діють лише на найближчий внутрішній цикл, у якому вони розміщені. Якщо необхідно з глибини внутрішнього циклу повністю вийти із зовнішнього циклу (або перейти на наступну ітерацію зовнішнього циклу), перед зовнішнім циклом ставиться мітка (наприклад, `searchLoop:`), після чого викликається `break searchLoop;` або `continue searchLoop;`.  
Це безпечний структурний механізм, який не дозволяє довільних стрибків у випадкові місця коду, як це робив `goto`.

### 13. До якого результату призведе виконання наступного фрагменту коду? Перевірте. Поясніть.
```java

boolean b = false;
if (a=false) {
    System.out.println("a is false");
}
if (b=true) {
    System.out.println("b is true");
}
if (a=b) {
    System.out.println("a = b");
}
```
**Результат роботи:**
```text
b is true
a = b
```
**Пояснення:**
У круглих дужках оператора `if` використано оператор присвоювання `=`, а не оператор порівняння `==`!
В мові Java оператор присвоювання повертає присвоєне значення:
1. `if (a = false)` присвоює змінній `a` значення `false` і повертає `false`. Оскільки умова хибна, тіло `if` не виконується (рядок `"a is false"` не друкується).
2. `if (b = true)` присвоює змінній `b` значення `true` і повертає `true`. Умова істинна, тому виконується `System.out.println("b is true");`.
3. `if (a = b)` присвоює змінній `a` поточне значення змінної `b` (яке на попередньому кроці стало `true`). Вираз повертає `true`, умова є істинною, тому виконується `System.out.println("a = b");`.

### 14. До якого результату призведе виконання наступного фрагменту коду? Перевірте. Поясніть.
```java
int a = 1;
a++;
++a;
switch(a) {
    case 1: System.out.println("1");
    case 2: System.out.println("2");
    case 3: System.out.println("3");
    case 4: System.out.println("4");
}
```
**Результат роботи:**
```text
3
4
```
**Пояснення:**
1. Початково `a = 1`.
2. Постфіксний інкремент `a++` збільшує значення `a` до 2.
3. Префіксний інкремент `++a` збільшує значення `a` до 3.
4. В операторі `switch(a)` значення `a` (3) збігається з міткою `case 3:`. Виконується команда `System.out.println("3");`.
5. Оскільки в блоці `case 3:` відсутній оператор `break`, спрацьовує механізм «провалювання» (fall-through): виконання продовжується у наступний блок `case 4:`, де друкується `"4"`.

### 15. До якого результату призведе виконання наступного фрагменту коду (true/false)? Перевірте. Поясніть.
```java
double sum = 0;
// Let's find: 1 + 1/2 + 1/3 + 1/4 + 1/5 + ...
for(int i=1; i<10; i++) {
    sum = sum + 1/i;
}
System.out.println(sum > 1);
```
**Результат роботи:**
```text
false
```
**Пояснення:**
У виразі `1 / i` константа `1` та змінна циклу `i` обидві мають цілочисельний тип `int`. У мові Java при діленні двох цілих чисел виконується **цілочисельне ділення** (дробова частина просто відкидається):
- При $i = 1$: `1 / 1 = 1`, `sum` стає $0.0 + 1 = 1.0$.
- При всіх наступних $i \in [2; 9]$: результат `1 / i` дорівнює `0` ($1/2 = 0$, $1/3 = 0$ тощо). До змінної `sum` щоразу додається `0`.
Після виходу з циклу значення `sum` дорівнює строго `1.0`.  
Вираз `sum > 1` еквівалентний перевірці `1.0 > 1`, яка є **`false`**.  
*(Щоб виконувалося ділення з плаваючою комою, один з операндів мав бути типу `double`, наприклад: `1.0 / i` або `(double) 1 / i`).*
