#### 2. Опис алгоритму та обробка виключних ситуацій
- **Вхідні дані:** масив цілих чисел `int[] array`.
- **Критерій кратності:** елемент $x$ є кратним 5, якщо залишок від ділення на 5 дорівнює 0 (`x % 5 == 0`). Зауважимо, що нуль ($0$) та від'ємні числа (наприклад, $-10, -25$) також враховуються згідно з математичним означенням подільності.

### Завдання №2 (Таблиця 2, №36)

#### 1. Формулювання
Визначити середнє геометричне номерів максимального та мінімального елементів масиву цілих чисел. Відповідно до вимог методичних вказівок, у цьому завданні обов'язково застосовано цикл `for`.

#### 2. Опис алгоритму та математичний зміст
- **Поняття номера елемента:** на відміну від 0-based індексу в Java ($0, 1, \dots, n-1$), порядковий номер елемента в масиві традиційно є 1-based значенням ($1, 2, \dots, n$). Це гарантує, що номери завжди є строго додатними натуральними числами ($pos \ge 1$), що принципово важливо для обчислення середнього геометричного.
- **Формула середнього геометричного двох чисел:**
  $$G = \sqrt{pos_{\min} \cdot pos_{\max}}$$
- **Цикл `for`:** використовується індексний цикл від $1$ до $n-1$ для одночасного пошуку індексів мінімального (`minIndex`) та максимального (`maxIndex`) елементів. Якщо зустрічається кілька однакових мінімумів або максимумів, фіксується перший за порядком.
- **Валідація аргументів:**
  - Якщо передано `array == null`, метод викидає `NullPointerException("Масив не може бути null")`.
  - Якщо масив порожній (`array.length == 0`), метод викидає `IllegalArgumentException("Масив не може бути порожнім")`.

### Завдання №3 (Таблиця 2, №66)

#### 1. Формулювання
Задано масиви $A(n)$ та $B(m)$. Сформувати масив $C(n+m)$, елементами якого є $n$ елементів масиву $A$, за якими слідують $m$ елементів масиву $B$.

#### 2. Опис алгоритму та робота з пам'яттю
- Створюється новий масив $C$ довжиною `a.length + b.length`.
- За допомогою двох послідовних циклів елементи масиву $A$ копіюються на позиції від $0$ до $n-1$, після чого елементи масиву $B$ розміщуються на позиції від $n$ до $n+m-1$ (`c[a.length + j] = b[j]`).
- Алгоритм коректно працює також з порожніми масивами (наприклад, об'єднання порожнього та непорожнього масивів).
- **Валідація аргументів:**
  - Якщо `a == null` або `b == null`, викидається `NullPointerException` з відповідним повідомленням про те, який саме масив є `null`.

#### 3. Результати тестування класу `Task3`
```text
A: [1, 2, 3], B: [4, 5, 6, 7] -> C: [1, 2, 3, 4, 5, 6, 7]
A: [10], B: [20] -> C: [10, 20]
A: [], B: [1, 2, 3] -> C: [1, 2, 3]
A: [9, 8, 7], B: [] -> C: [9, 8, 7]
A: [], B: [] -> C: []
A: [-5, 0, 5], B: [15, -20] -> C: [-5, 0, 5, 15, -20]
A: null, B: [1, 2] -> EXCEPTION (NPE)! Масив A не може бути null
A: [1, 2], B: null -> EXCEPTION (NPE)! Масив B не може бути null
A: null, B: null -> EXCEPTION (NPE)! Масив A не може бути null
```

## Частина 2. Відповіді на контрольні запитання

### 1. Чим змінна відрізняється від масиву?
- **Звичайна (скалярна) змінна** — це іменована область пам'яті, що зберігає одне-єдине значення певного типу (наприклад, одне число `int x = 5`).
- **Масив** — це впорядкована структура даних фіксованого розміру, яка зберігає сукупність (послідовність) однотипних елементів у неперервній області пам'яті. Доступ до окремих елементів масиву здійснюється за їхнім числовим індексом за константний час $O(1)$. Крім того, у Java масив завжди є повноцінним об'єктом.

---

### 2. Що таке стек? Що таке купа? Яка між ними різниця?
- **Стек (Stack Memory):**
  - Область пам'яті, що працює за принципом **LIFO** (Last In, First Out).
  - Використовується для виконання потоків, збереження кадрів виклику методів (stack frames), локальних примітивних змінних та посилань на об'єкти.
  - Виділення та звільнення пам'яті відбувається автоматично і блискавично (простим зсувом вказівника стека при вході/виході з методу). Розмір стека обмежений (переповнення призводить до `StackOverflowError`).
- **Купа (Heap Memory):**
  - Загальна динамічна область пам'яті JVM, де створюються і зберігаються **всі об'єкти та масиви**.
  - Пам'ять виділяється оператором `new` під час виконання програми.
  - Очищення невикористовуваної пам'яті здійснюється автоматичним збирачем сміття (Garbage Collector). Доступ до купи дещо повільніший, ніж до стека, але обсяг купи значно більший (переповнення викликає `OutOfMemoryError`).

| Критерій | Стек (Stack) | Купа (Heap) |
| :--- | :--- | :--- |
| **Що зберігає** | Локальні змінні, кадри методів, посилання | Усі об'єкти, масиви, екземпляри класів |
| **Швидкість** | Дуже швидкий | Повільніший через динамічне виділення та GC |
| **Управління** | Автоматично процесором/потоком (LIFO) | Збирач сміття (Garbage Collector) |
| **Видимість** | Локальна для потоку (Thread-safe) | Спільна для всього застосунку |

---

### 3. Чи може змінна бути розташована у стеку? Безпосередньо у купі? В об’єкті у купі? Чи може масив бути розташований у стеку? Безпосередньо у купі? В об’єкті у купі?
- **Змінна:**
  - **У стеку:** так, якщо це локальна змінна методу примітивного типу або локальне посилання.
  - **Безпосередньо у купі:** ні, змінні у купі існують виключно як поля об'єктів або елементи масивів.
  - **В об'єкті у купі:** так, усі поля (fields) об'єктів (як примітивні, так і посилальні) зберігаються всередині самого об'єкта в купі.
- **Масив:**
  - **У стеку:** **ні**, у Java масиви є об'єктами і фізично **завжди** розміщуються в купі (Heap). У стеку може розташовуватися лише локальна змінна-посилання на цей масив (хоча сучасний JIT-компілятор у процесі Escape Analysis може оптимізувати скаляри, семантично масив завжди в купі).
  - **Безпосередньо у купі:** **так**, екземпляр масиву як самостійний об'єкт створюється в купі (`new int[10]`).
  - **В об'єкті у купі:** поле об'єкта містить посилання на масив, а сам масив як самостійна структура також знаходиться поруч у купі.

---

### 4. Чим посилання на масив відрізняється від масиву? Чи може посилання на масив бути розташовано у стеку? Безпосередньо у купі? В об’єкті у купі?
- **Різниця:**
  - **Масив** — це власне сам блок даних у купі, що містить заголовок об'єкта (метадані, поле `length`) та послідовність збережених значень.
  - **Посилання на масив** — це адреса (покажчик) у пам'яті, що вказує на місце розташування масиву в купі.
- **Розташування посилання:**
  - **У стеку:** **так**, якщо це локальна змінна методу (`int[] arr = new int[5];` — `arr` у стеку).
  - **Безпосередньо у купі:** ні (посилання в купі завжди є або полем об'єкта, або елементом масиву посилань).
  - **В об’єкті у купі:** **так**, якщо масив є полем іншого класу (`class Container { int[] data; }`), посилання `data` розташоване всередині об'єкта в купі.

---

### 5. Якщо масив складається з 10 комірок, які індекси мають перша та остання комірки?
- У Java індексація масивів завжди починається з **0**.
- **Перша комірка:** індекс **`0`**.
- **Остання комірка:** індекс **`9`** (`array.length - 1` = $10 - 1 = 9$).

---

### 6. Що буде, якщо звернутися до неіснуючої комірки у масиві?
У середовищі виконання Java буде негайно згенеровано виключення (runtime exception) **`java.lang.ArrayIndexOutOfBoundsException`**, і поточне виконання методу аварійно перерветься (якщо виключення не перехоплено блоком `try-catch`). 

На відміну від мов на зразок C/C++, у Java вихід за межі масиву суворо контролюється віртуальною машиною JVM, що унеможливлює пошкодження пам'яті за межами виділеного буфера.

---

### 7. При створенні нового масиву без явної ініціалізації усі його комірки будуть проініціалізовані:
- **спеціальними значеннями за замовчуванням?** — **ТАК, САМЕ ТАК.**
- довільними значеннями, що знаходяться в цей час у пам’яті, яку виділено під масив? — Ні, JVM гарантує повне занулення пам'яті.

**Значення за замовчуванням у Java:**
- Числові цілі типи (`byte`, `short`, `int`, `long`): `0` (або `0L`)
- Дійсні числа (`float`, `double`): `0.0f` / `0.0d`
- Символьний тип (`char`): `'\u0000'` (null-character)
- Логічний тип (`boolean`): `false`
- Будь-які посилальні типи (об'єкти, рядки, масиви): `null`

### 8. Як дізнатися номер першої та останньої комірки масиву, якщо відомо лише посилання на нього?
Маючи посилання на масив `arr`:
- **Перша комірка:**
  - Індекс: завжди **`0`** (за умови `arr.length > 0`).
  - Порядковий номер (1-based): **`1`**.
- **Остання комірка:**
  - Індекс: вираз **`arr.length - 1`**.
  - Порядковий номер (1-based): вираз **`arr.length`**.
- *Примітка:* якщо `arr.length == 0` (масив порожній), комірок у масиві взагалі немає, і звернення до `arr[0]` викличе `ArrayIndexOutOfBoundsException`.

---

### 9. Як змінити розмір масиву?
**Ніяк.** У Java розмір одного разу створеного масиву є **незмінним** (fixed size), оскільки під нього виділяється фіксований суцільний блок пам'яті в купі.

Щоб "змінити" розмір, створюють **новий масив** бажаного розміру та копіюють у нього елементи старого масиву за допомогою:
1. `System.arraycopy(oldArr, 0, newArr, 0, count)`
2. `Arrays.copyOf(oldArr, newLength)`
3. Ручного циклу `for`

Якщо в програмі потрібна динамічна зміна кількості елементів без ручного перестворення, використовують класи колекцій, наприклад `ArrayList`.

---

### 10. Що відбувається з масивом при копіюванні посилання на нього?
При копіюванні посилання (наприклад, `int[] b = a;`):
- Новий масив **НЕ створюється**.
- У змінну `b` просто копіюється адреса пам'яті, яка зберігалася в `a`.
- Обидва посилання (`a` та `b`) тепер вказують на **один і той самий об'єкт масиву** в купі.
- Будь-яка модифікація елементів через одне посилання (наприклад, `b[0] = 999;`) негайно відображається при зверненні через інше (`a[0]` також стане 999).

---

### 11. Що відбувається з масивом при втрачанні посилання на нього?
Коли на масив у купі більше не вказує жодне активне посилання (наприклад, змінна вийшла з області видимості, їй присвоєно `null` або іншу адресу):
- Об'єкт масиву стає **недосяжним** (unreachable).
- Масив помічається як сміття та підлягає видаленню **збирачем сміття (Garbage Collector)**.
- Під час чергового циклу GC пам'ять у купі, яку займав масив, звільняється та повертається системі для повторного використання.

### 12. Чим відрізняються конструкції «for» та «for-each» при роботі з масивами? Які переваги та недоліки кожного з варіантів?

| Характеристика | Класичний цикл `for` | Цикл `for-each` (`for (Type x : arr)`) |
| :--- | :--- | :--- |
| **Доступ до індексу** | Є повний доступ до лічильника $i$. Можна дізнатися номер/індекс елемента. | Індекс прихований, доступне лише значення елемента. |
| **Зміна елементів масиву** | **Можна** змінювати елементи (`arr[i] = val`). | **Неможливо** перезаписати комірку масиву (змінна ітератора є локальною копією значення). |
| **Крок та напрямок** | Довільний: з кінця до початку, через один крок ($i+=2$), діапазони. | Лише послідовний перебір усіх елементів від початку до кінця з кроком 1. |
| **Ризик виходу за межі** | Можлива помилка "Off-by-one" (`<= arr.length` замість `<`). | Вихід за межі масиву неможливий в принципі. |
| **Читабельність** | Більш громіздкий синтаксис. | Чистий, компактний та декларативний код. |

---

### 13. Чи можна у масив «double[]» записати значення «int»? Чи можна у масив «int[]» записати значення «double»?
- **Запис `int` у `double[]`:** **ТАК, МОЖНА.**
  Відбувається автоматичне неявне розширення типу (widening primitive conversion) без втрати точності: значення цілого числа `int` автоматично перетворюється на відповідне дійсне `double` (наприклад, `42` перетворюється на `42.0`).
- **Запис `double` у `int[]`:** **НІ, БЕЗПОСЕРЕДНЬО НЕ МОЖНА.**
  Спроба записати `intArr[0] = 3.14;` призведе до **помилки компіляції** (*Type mismatch: cannot convert from double to int*), оскільки звуження типу (narrowing conversion) може призвести до втрати точності та відкидання дробової частини. Це дозволено зробити лише через **явне приведення типів** (кастування): `intArr[0] = (int) 3.14;`, у результаті чого запишеться ціле число `3`.
